# mtncloud_router (Resource)

Manages a Morpheus network router. Type-specific options depend on the router types available in your MTN Cloud account. Creation records the router ID without waiting for backend provisioning to finish.

## Example Usage

```terraform
# Discover the actual type code and its options using mtncloud_router_types.
# This variable must identify a creatable type without a network server.
variable "router_type" {
  type        = string
  description = "Router type code available in your account."
}

resource "mtncloud_router" "app" {
  name  = "app-router"
  group = "MTNNG_CLOUD_AZ_1"
  type  = var.router_type

  # Set cloud_id if the group has more than one cloud.
  # Supply any required type-specific options using options_json = jsonencode({...}).
  # Use the API optionTypes metadata; option names vary by backend.
}
```

## Type-specific configuration

First inspect `jsondecode(data.mtncloud_router_types.available.types_json)`.
Choose a creatable type and use its `optionTypes` metadata to construct
`options_json`, a JSON object merged directly into `networkRouter` in the create
request. Use the nested API payload shape; do not assume option names from a
different router backend apply to your account.

Only `name` and `enabled` update in place. Changes to scope, type, or
`options_json` replace the router. Options are not read back, so Terraform cannot
detect remote changes to them. Import does not recover them; adding options to an
imported router proposes replacement. Review the plan before applying.

For cloud-backed types, `cloud_id` must belong to the selected group. It can be
omitted only when that group has exactly one cloud. For types with
`hasNetworkServer=true`, set `network_server_id` instead. Provider resource-pool
and availability-zone defaults are not used for routers.

Creation records the returned ID and reads the router but does not wait for
backend readiness. This resource does not separately manage router interfaces,
NAT rules, routes, or firewall rules. Type-specific options and permissions must
be verified against your MTN Cloud deployment before production use.

## Schema

### Required

- `name` (String) Router name.
- `type` (String) Router type name or code from mtncloud_router_types. Changes replace the router.

### Optional

- `cloud_id` (Number) Cloud ID for types without a network server. Inferred only when the group has exactly one cloud. Changes replace the router.
- `enabled` (Boolean) Whether the router is enabled.
- `group` (String) Group name; defaults to the provider group. Changes replace the router. Shared routers are not supported.
- `network_server_id` (Number) Required for router types with hasNetworkServer=true; conflicts with cloud_id. Changes replace the router.
- `options_json` (String, Sensitive) JSON object of additional fields inside networkRouter, based on the selected type's optionTypes (for example config or interfaces). Cannot override core attributes. Sent only on create; changes replace the router. Remote drift is not tracked and import cannot recover this value. Sensitive values remain in Terraform state.

### Read-Only

- `external_ip` (String) External IP, if assigned.
- `id` (String) Numeric router ID.
- `status` (String) Observed router status; creation does not wait for readiness.
